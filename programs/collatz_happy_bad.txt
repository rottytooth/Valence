COLLATZ / HAPPY
collatz_happy.val, annotated

One program, two readings:
  * reading 0 runs the Collatz sequence, stopping at 1
  * reading 1 runs the Happy Number process (n -> sum of the squares of its
    digits), stopping when a value repeats

Starting from 11, the output is:
  reading 0:  11 34 17 52 26 13 40 20 10 5 16 8 4 2 1
  reading 1:  11 2 4 16 37 58 89 145 42 20 4

Both readings share one loop. A single mode variable (𐆊) is set to 0 or 1 by
the only ambiguous line in the program (line 3). The program then checks 𐆊
four times: during setup, to pick the step, to pick the stopping rule, and to
choose how to set the loop flag before the first pass.


VARIABLES
---------
  𐅶  n       the current value in the sequence
  𐆇  go      loop flag; the loop runs while it is > 0
  𐆊  mode    0 = Collatz, 1 = Happy
  𐆋  seen    queue of values seen so far (Happy only)
  𐆉  sum     running sum of squared digits (Happy only)
  𐆁  r       Happy: remaining digits / current digit
             Collatz: n mod 2
  𐅻  d       Happy: r div 10;  Collatz: n div 2
             also the item variable when scanning the seen queue
  𐅾  copy    throwaway copy of seen, consumed by the scan

All eight variables are in use.


THE PROGRAM
-----------
Each Valence line is followed by the interpreter's own reading of it
(indented to show block structure) and a note.

-- setup --

 1  [𐅶]𐆉[[𐅻[𐆇𐆇]]𐅶[𐆇𐆋]]
        𐅶 = ((1*8) + 3)
    n = 11 (0o13). This is the starting number.

 2  [𐆇]𐆉[𐆇𐅶]
        𐆇 = 0
    go = 0. This is temporary: line 3 needs 𐆇 to hold something other than 1.

 3  [𐆊]𐆉[𐆇]
        reading 0:  𐆊 = 𐆇      (mode = 0, the value of variable 𐆇)
        reading 1:  𐆊 = 1      (mode = 1, the digit 1)
    *** THE SPLIT ***
    𐆇 stands alone where an expression is expected, so the parser cannot tell
    whether it's the variable or the digit, and both readings survive.
    Every variable starts out holding its own digit (𐆇 = 1), so line 2
    first sets 𐆇 to 0 to make the two readings differ. This is the only line
    with more than one reading, so the program has exactly two
    interpretations.

        𐆇 = 1
    go = 1. Now 𐆇 is the loop flag.

    Print the starting number.

    Happy: seen = [n]. 𐆋 is read twice here: as a variable on the left and as
    the type "queue" inside the cast.

11  𐅶[𐅾𐆇]

    Loop while go > 0. Ints count as true only when positive.

16  [𐅻]𐆉[[[𐅾𐆁]𐆇[𐆇𐅻]]𐅾[[𐅻[𐆇𐆇]]𐅶[𐆇𐅾]]]

    d = (r - 5) / 10. Valence ints round (JavaScript's Math.round) instead of
    truncating, so shifting by half the divisor turns the rounding into a
    floor: (r - 5) / 10 rounds to floor(r / 10) for every r >= 0.

                    𐆁 = 𐅻
    r = the remaining digits

            print(𐅶)

NOTES
-----
* Every line is fully bracketed, so each one parses to exactly one reading
  except line 3. The program has exactly two interpretations.

* The mode variable is the only thing that tells the two readings apart.
  The two processes share one loop, one print, and the variables 𐆁 and 𐅻.

* Happy mode really does detect repetition: it keeps a queue of every value
  it has seen and compares each new value against it. It does not use the
  shortcut of stopping at 1 or 4. A happy number therefore ends "... 1 1",
  because 1 maps to itself. An unhappy number ends on whichever value of
  the cycle 4 16 37 58 89 145 42 20 it reaches first.

* To change the starting number, edit line 1 (an octal expression). Under
  64 it is n = [𐅻[𐆇a]]𐅶[𐆇b], where a and b are the octal digits. Examples:
     7:  Collatz 7 22 11 34 17 52 26 13 40 20 10 5 16 8 4 2 1
         Happy   7 49 97 130 10 1 1
     9:  Collatz 9 28 14 7 22 11 34 17 52 26 13 40 20 10 5 16 8 4 2 1
         Happy   9 81 65 61 37 58 89 145 42 20 4 16 37

* Tested in Node against the current interpreter, with both readings
  checked against a reference JavaScript implementation. Starting values
  tested: 1-13, 19, 27 (its Collatz run peaks at 9232), 44 and 63.

* Run time: at the web console's default speed of one line per second, the
  starting value of 11 takes about 4 minutes (Collatz) and 8 minutes
  (Happy). The Happy reading is slower because it rescans the seen queue
  on every step.

* Don't paste this .txt into the web console. The editor turns Roman
  letters (q w e a s d z x) into Valence signs, so it would garble the
  program. Use the .val file, which contains code only.
