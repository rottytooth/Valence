COLLATZ / HAPPY, SECOND VERSION
SECOND_collatz.val, annotated (written in "typed as" letters)

One program, two readings:
  * W = 0: the Collatz sequence, stopping at 1
  * W = 1: the Happy Number process, stopping at 1 or 4

How it works: no ifs choose between the two processes. Instead, the mode
variable W (0 or 1) is used as a number inside the arithmetic, and both
processes run through the same lines.

Each step splits n into a quotient and a remainder in base
b = 2 + 8W, so b is 2 for Collatz and 10 for Happy.
  * Happy keeps splitting off base-10 digits and adds up their squares.
  * Collatz needs only the lowest binary digit (whether n is odd), so it
    stops after one pass, and an extra term (zeroed out when W = 1) turns
    that digit into either n/2 or 3n+1.

Starting from 7, the output is:
  W = 0:  7 22 11 34 17 52 26 13 40 20 10 5 16 8 4 2 1
  W = 1:  7 49 97 130 10 1

FIXES: lines 8 and 11 have been corrected from the first draft (see the
notes on those lines). Before the fixes, the output from 7 was:
  W = 0:  7 97 12202 186135409 ... Infinity NaN 0
  W = 1:  7 10 1


VARIABLES
---------
  X  𐆁  n: the current value. Inside the inner loop it holds the digits
           not yet processed.
  W  𐆇  mode: 0 = Collatz, 1 = Happy
  Z  𐆊  accumulator for the next value of n
  Q  𐅶  quotient: X div b
  A  𐆋  remainder: X mod b (a decimal digit, or n's parity)

E, S and D are not used as variables.


THE PROGRAM
-----------
Each line in letters is followed by its Valence signs, the interpreter's own
reading of it (indented to show block structure), and a note.

 1  [X]S[WX]                 [𐆁]𐆉[𐆇𐆁]
        X = 7
    The starting number. "WX" reads X as the digit 7.

 2  [W]S[WQ]                 [𐆇]𐆉[𐆇𐅶]
        W = 0
    Every variable starts out holding its own digit (W = 1), so W is set to
    0 here. That's what makes the next line ambiguous in a useful way.

 3  [W]S[W]                  [𐆇]𐆉[𐆇]
        reading 0:  W = W      (W stays 0: Collatz)
        reading 1:  W = 1      (the digit 1: Happy)
    *** THE SPLIT ***
    The W on the right stands alone where an expression is expected, so it
    can be either the variable or the digit. One reading assigns W to
    itself, which changes nothing. This is the only line with two readings,
    so the program has exactly two interpretations.

 4  A[EX]                    𐆋[𐅾𐆁]
        print(X)
    Print the starting number.

 5  Q[[WW]W[[[EX]A[WW]]Q[[EX]A[[WS]X[EW]]]]]
                             𐅶[[𐆇𐆇]𐆇[[[𐅾𐆁]𐆋[𐆇𐆇]]𐅶[[𐅾𐆁]𐆋[[𐆇𐆉]𐆁[𐅾𐆇]]]]]
        while((1 - ((X == 1) + (X == (4 * W))))) {
    The outer loop runs until n is 1, or until n is 4W. Each comparison
    counts as 1 or 0, so the loop continues while neither is true.
      Collatz: 4W = 0, and n never reaches 0, so it stops only at 1.
      Happy:   stops at 1 (happy) or 4 (unhappy). Every unhappy number ends
               up in the cycle 4 16 37 58 89 145 42 20, so reaching 4
               stands in for detecting a repeat.

 6  [Z]S[WQ]                 [𐆊]𐆉[𐆇𐅶]
            Z = 0
    Clear the accumulator.

 7  Q[EX]                    𐅶[𐅾𐆁]
            while(X) {
    Inner loop: each pass splits off one base-b digit of X.

 8  [Q]S[S[[[X]S[[EX]W[[WW]Q[[WS]X[EW]]]]]E[[WE]Q[D[EW]]]]]
                             [𐅶]𐆉[𐆉[[[𐆁]𐆉[[𐅾𐆁]𐆇[[𐆇𐆇]𐅶[[𐆇𐆉]𐆁[𐅾𐆇]]]]]𐅾[[𐆇𐅾]𐅶[𐅻[𐅾𐆇]]]]]
                Q = int((cast(ratio,(X - (1 + (4 * W)))) / (2 + (W*8))))
    Q = floor(X / b), where b = 2 + 8W.
    int() rounds to the nearest integer; it doesn't floor (Math.round).
    Subtracting half the base first, 1 + 4W, turns the rounding into a
    floor: (X - b/2) / b always rounds to floor(X / b), since JavaScript
    rounds .5 upward. The half-base is also scaled by W.
    FIXED: the first draft divided X itself:
      [Q]S[S[[[X]S[EX]]E[[WE]Q[D[EW]]]]]
    That made 7/2 round to 4 and 7/10 round to 1, so line 9 produced
    negative remainders.
    (The ratio cast isn't needed, because Int division rounds the same way.
    It does no harm, though.)

 9  [A]S[[EX]W[[EQ]X[[WE]Q[D[EW]]]]]
                             [𐆋]𐆉[[𐅾𐆁]𐆇[[𐅾𐅶]𐆁[[𐆇𐅾]𐅶[𐅻[𐅾𐆇]]]]]
                A = (X - (Q * (2 + (W*8))))
    A = X mod b: the last decimal digit (Happy), or 0/1 for even/odd
    (Collatz).

10  [Z]Q[[EA]X[EA]]          [𐆊]𐅶[[𐅾𐆋]𐆁[𐅾𐆋]]
                Z += (A * A)
    Happy: add the square of the digit.
    Collatz: A is 0 or 1, so this just adds A. Line 11 relies on that.

11  [Z]Q[[[WW]W[EW]]X[[EQ]Q[[EA]X[[[WD]X[EQ]]Q[WA]]]]]
                             [𐆊]𐅶[[[𐆇𐆇]𐆇[𐅾𐆇]]𐆁[[𐅾𐅶]𐅶[[𐅾𐆋]𐆁[[[𐆇𐅻]𐆁[𐅾𐅶]]𐅶[𐆇𐆋]]]]]
                Z += ((1 - W) * (Q + (A * ((5 * Q) + 3))))
    The Collatz step. The (1 - W) factor makes this 0 in Happy mode.
    Together with the A added in line 10, it gives:
      n even (A = 0):  Z = Q                          = n / 2
      n odd  (A = 1):  Z = 1 + Q + 5Q + 3 = 6Q + 4    = 3n + 1
                       (because n = 2Q + 1)
    So the parity bit A chooses between the two Collatz rules through
    multiplication, with no if.
    FIXED: the first draft had Q where the A is (...Q[[EQ]X[...),
    which made the term Q + Q(5Q + 3). That grows with Q squared, so the
    values blew up.

12  [X]S[[EW]X[EQ]]          [𐆁]𐆉[[𐅾𐆇]𐆁[𐅾𐅶]]
                X = (W * Q)
    Happy: X = Q, the digits still left, so the inner loop continues.
    Collatz: X = 0, so the inner loop ends after one pass, since only the
    lowest bit was needed.

13  E                        𐅾
            }
    End of the inner loop.

14  [X]S[EZ]                 [𐆁]𐆉[𐅾𐆊]
            X = Z
    n = the next value.

15  A[[D]S[D[WS]]]           𐆋[[𐅻]𐆉[𐅻[𐆇𐆉]]]
            print(cast(char,(4*8)))
    Print a space (0o40) as a separator.

16  A[EX]                    𐆋[𐅾𐆁]
            print(X)
    Print n.

17  E                        𐅾
        }
    End of the outer loop.


NOTES
-----
* Where W appears: it's never the condition of an if. It's used as a
  number in line 5 (the stop value 4W), lines 8 and 9 (the base 2 + 8W),
  line 11 (the 1 - W factor) and line 12 (the W * Q factor).

* No if anywhere: the two readings run exactly the same lines in the same
  order. Only the inner loop's pass count differs: once for Collatz, once
  per digit for Happy. That comes from X = W * Q, not from a branch.

* Tested in Node against the current interpreter. Both readings match a
  reference JavaScript implementation for starting values 1-13, 19, 27, 44
  and 63.

* To change the starting number, edit line 1. Under 64 it is
  [X]S[[D[Wa]]Q[Wb]], where a and b are the octal digits.

* This is a .txt, not the program itself. The web editor turns the letters
  q w e a s d z x into Valence signs, so pasting this file would garble it.
  Use SECOND_collatz.val instead.
